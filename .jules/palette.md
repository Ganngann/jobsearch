## 2024-05-19 - Keyboard Accessibility for Hover-Revealed Actions
**Learning:** In the CV components, there are many action buttons (e.g., delete, add) that are hidden by default using `opacity-0` and revealed on hover using `group-hover:opacity-100`. This hides the actions from keyboard users (tabbing) because the elements don't become visible when focused.
**Action:** When hiding elements visually with Tailwind's `opacity-0 group-hover:opacity-100`, always pair it with `focus-within:opacity-100` (on the parent group) or `focus:opacity-100` (on the element itself) to ensure they are visible when receiving keyboard focus.
## 2024-07-14 - Accessibility and Visual Focus for Icon-Only Buttons
**Learning:** Icon-only buttons used for actions (like add or delete) were missing explicit ARIA labels and native title tooltips, making them opaque to screen reader users and non-obvious to sighted users lacking hover context. Furthermore, interactive icon-only buttons lacked a clear visual focus indicator when navigated via keyboard. Finally, the inner SVG elements were not hidden from screen readers.
**Action:** For all icon-only action buttons (e.g., `<button>` containing only an `<svg>`), strictly ensure the inclusion of a descriptive `aria-label` attribute (in French) AND a matching `title` attribute for native tooltips. Provide a clear visual focus indicator using `focus-visible:ring-2 focus-visible:outline-none`. For the inner `<svg>` element, always include `aria-hidden="true"` so screen readers ignore the decorative graphic.
