## 2024-05-19 - Keyboard Accessibility for Hover-Revealed Actions
**Learning:** In the CV components, there are many action buttons (e.g., delete, add) that are hidden by default using `opacity-0` and revealed on hover using `group-hover:opacity-100`. This hides the actions from keyboard users (tabbing) because the elements don't become visible when focused.
**Action:** When hiding elements visually with Tailwind's `opacity-0 group-hover:opacity-100`, always pair it with `focus-within:opacity-100` (on the parent group) or `focus:opacity-100` (on the element itself) to ensure they are visible when receiving keyboard focus.
## 2026-07-17 - Icon-Only Button Accessibility Pattern
**Learning:** When addressing screen-reader accessibility for form inputs that have icon-only submit buttons, attempting to add `aria-label` directly to the `<input>` is an anti-pattern in this codebase. Instead, the correct pattern requires adding a visually hidden `<label class="sr-only">` that explicitly links to the `<input>` using unique `for` and `id` attributes. Additionally, the adjacent icon-only `<button>` must have its own `aria-label` for screen readers, a `title` for mouse tooltips (in French), `focus-visible` utility classes for keyboard navigation, and the inner `<svg>` must be marked with `aria-hidden="true"` to prevent redundant announcements.
**Action:** Always implement the `sr-only` label pattern with unique IDs for form inputs, and ensure icon-only buttons receive the full complement of accessibility attributes (`aria-label`, `title`, `focus-visible`, and `aria-hidden="true"` on the SVG).
